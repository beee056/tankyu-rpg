# 探究学習RPG コンセプトドラフト v0.1

> **ステータス**: 初期たたき台 — 議論・修正を前提とした複数案提示  
> **作成日**: 2026-05-18  
> **作成主体**: PIVOT&QUEST（LIGHTHOUSE運営）向け設計検討用

## 1. コアコンセプト

**「自分の問いを旅する物語ゲーム — 答えではなく、問いそのものが主人公を育てる」**

プレイヤーは"探究者"として世界に放り込まれ、外部から与えられた答えではなく、自分自身の問いを磨くことでキャラクターが成長する。AIは答えを持たない──問いを返すだけだ。

---

## 2. コアループ

```
問いに出会う
    ↓
世界を探索する（情報収集・対話・発見）
    ↓
選択肢に迷う（分岐: 複数の解釈が存在する）
    ↓
内省する（プレイヤー自身の言葉で記述する）
    ↓
気づきを結晶化する（スキル・称号・日誌に刻まれる）
    ↓
新たな・より深い問いへ
```

### 成長・分岐・物語の絡み方

| 要素 | ループ内での役割 |
|------|----------------|
| **成長** | 内省の質と量が「探究力4軸」を伸ばす。正解を選ぶのではなく、自分の言葉で記述したときに経験値が入る |
| **分岐** | 世界の見え方が変わる。ルートが違えば出会う問いも違う。ただし"詰み"は存在しない |
| **物語** | プレイヤーの内省ログが物語の一部になる。世界の謎は"探究のプロセス"そのものが解く鍵 |

## 3. 世界観・主人公・物語骨格（3案）

### 案A：「霧の大陸クエスティア」（ハイファンタジー）

**世界観**  
かつて「大いなる問い」によって築かれた大陸。人々は問いを嫌い、簡単な答えを求めるようになったとき、世界は霧に包まれ始めた。霧の中には怪物ではなく「未解決の問い」が潜んでいる。

**主人公**  
問いを持って生まれた少年/少女「クエスト」。古い図書館の精霊と出会い、霧を晴らすために旅に出る。

**物語骨格**  
- 各地域 = 探究の各フェーズを象徴（課題発見の森、情報収集の港町、分析の迷宮、表現の王都）
- ラスボスは「完璧な答えを持つ存在」= 思考停止の象徴
- プレイヤー自身の探究テーマが「自分だけの霧」を晴らしていく

**ゲームデザイン論的根拠**  
空間的メタファーによる抽象概念の具象化。『Journey』や『Outer Wilds』が示した「探索それ自体が学習」の設計思想。中高生に親しみやすい王道RPG文脈。

---

### 案B：「現代都市の探偵事務所」（リアル現代もの）

**世界観**  
現代日本。探偵事務所「LIGHTHOUSE」に持ち込まれる依頼は、すべて「誰かの問い」。SNSで流れる情報の真偽、まちの未解決問題、自分自身が感じた違和感。

**主人公**  
見習い探偵（＝プレイヤー）。ベテラン探偵はなぜか答えを教えてくれない。「依頼人の本当の問いは何か？」を突き止めることが仕事。

**物語骨格**  
- 各依頼 = 1つの探究テーマ（例:「なぜ商店街は衰退するのか」「友達とすれ違うのはなぜか」）
- 調査を進めると、依頼人の"表面の問い"の奥に"根本の問い"が見えてくる（=必然性の一本化）
- プレイヤー自身も「自分の依頼を持ち込む」エンドゲームコンテンツ

**ゲームデザイン論的根拠**  
中高生の共感を得やすい現代舞台。LIGHTHOUSEブランドを直接ゲーム内に組み込める。探偵 = 探究者の自然なメタファー。

---

### 案C：「記憶の海を航る船」（詩的SF）

**世界観**  
人類が集合知を持つ「記憶の海」が実在する近未来。しかし海は深すぎて、正しく読めた者しか宝を持ち帰れない。情報過多の時代に「問い」こそが羅針盤となる。

**主人公**  
記憶の海に落ちた少年/少女。AIナビゲーター（問いを返すだけのAI）と共に自分の記憶の源泉を探す。

**物語骨格**  
- 各"島" = 異なる情報の質（一次情報、二次情報、偏った情報、情動的情報）
- 情報リテラシーと探究力を同時に鍛える設計
- 「なぜ自分はここにいるのか」= 自己の必然性を探す旅

**ゲームデザイン論的根拠**  
情報リテラシー教育との親和性が高く、学校側の採用理由を広げる。SF設定は技術的未来感があり、AIとの関係性を正面から問える。

## 4. 「成長」のメカニクス

### 探究力4軸（ステータスシステム）

学習指導要領の「課題設定→情報収集→整理分析→まとめ表現」を直接マッピング。

| 軸 | ゲーム内名称 | 伸びる行動 | 可視化 |
|----|------------|-----------|--------|
| 課題発見力 | **問い力** | 問いを立てる・問いを深掘りする選択をした回数 | 泡/霧のビジュアル |
| 情報収集力 | **探索力** | 多様な情報源にアクセスした量・偏りの少なさ | 地図の広がり |
| 整理分析力 | **繋ぐ力** | 情報を構造化した記述の質（自由記述+チェックリスト） | クモの巣グラフ |
| まとめ表現力 | **伝える力** | 他者（NPC/クラスメート）に言語化して伝えた回数 | 声の波形 |

加えて、LIGHTHOUSEの4ステップとも連動：

| LIGHTHOUSEステップ | ゲーム内イベント |
|------------------|---------------|
| 省察 | 各チャプター末の「内省ジャーナル」記述 |
| 抽出 | NPC対話で「何が一番大事だった？」選択 |
| 接続 | 別チャプターの気づきと今の気づきをリンクするシステム |
| 証明 | 最終表現イベント（プレゼン/作品/問いの宣言） |

### スキルツリー構想

- レベルアップではなく「称号の解放」（例: 「問いの芽吹き」→「問いの耕作者」→「問いの建築家」）
- 数値ではなくプレイヤー自身の記述が「証拠」になる（ポートフォリオ的スキルツリー）
- 教員側には「どの軸がどの程度伸びているか」の数値ダッシュボードを別途提供

## 5. 「分岐」のメカニクス

### 分岐の哲学

**真の正解は存在しない。ただし、「自分の答え」の深さは存在する。**

| 分岐タイプ | 説明 | 教育的意図 |
|-----------|------|-----------|
| **認識の分岐** | 同じ出来事を「どう解釈するか」で世界の見え方が変わる | 複眼的思考・多面的観察 |
| **優先順位の分岐** | どの情報を重視するか。どの価値観を選ぶか | 意思決定プロセスの言語化 |
| **問いの深さの分岐** | 表面の問いに答えるか、根本の問いを探るかで物語の深度が変わる | 必然性の一本化への誘導 |
| **表現方法の分岐** | 結論を「論文風」「物語風」「図式」「問い形式」で表現できる | 表現形式の多様性・選択の自覚 |

### 「選択肢」の設計原則

1. 選択肢は「正しい/間違い」ではなく「どちらも意味がある」
2. 選んだ理由を1文で書かせる（「なぜこれを選んだか」）
3. 別ルートを後から振り返れる（他の選択肢の結果を一部見られる）
4. 教員は「クラス全体がどの選択肢を選んだか」を集計・比較できる

## 6. 「物語」の構造

### 章立てとプレイ時間設計

学校カリキュラム：年間35コマ（週1回 × 35週）を基準に設計。

```
プロローグ（1コマ）: 世界に入る。最初の「問い」に出会う
    ↓
第1章「問いを立てる」（5〜7コマ）
  - 課題発見・問いの設定・動機の言語化
  - ≈ 課題設定フェーズ
    ↓
第2章「世界を広げる」（7〜8コマ）
  - 情報収集・多様な視点との出会い・偏りへの気づき
  - ≈ 情報収集フェーズ
    ↓
第3章「繋いで考える」（7〜8コマ）
  - 整理・構造化・矛盾との直面・解釈の深化
  - ≈ 整理分析フェーズ
    ↓
第4章「伝えて変える」（7〜8コマ）
  - まとめ・表現・フィードバック・問いの更新
  - ≈ まとめ表現フェーズ
    ↓
エピローグ（2〜3コマ）: 旅の振り返り。次の問いの宣言
```

**合計: 約30〜35コマ（年間1周を想定）**

### カリキュラム連動設計

- 各章に「教員向け進行ガイド」を付属
- ゲーム内の記述（ジャーナル）が探究学習の「成果物」として提出可能
- 章末に「クラス共有タイム」誘発イベントを設置（ピア対話設計）

## 7. AIに頼らない設計の工夫

### 基本哲学

> AIは「問いを返す」存在であり、「答えを与える」存在ではない。  
> ゲーム内のAIキャラクター（ナビゲーター/精霊/パートナー）は、プレイヤーの発言に対して必ず「問いで返す」。

### 具体的なしかけ

| 仕掛け | 詳細 | 狙い |
|-------|------|------|
| **オープン入力必須** | 選択肢だけで進める場面を作らない。重要な分岐では必ず自由記述が必要 | 思考代行を防ぐ |
| **最低文字数ではなく「具体性チェック」** | 文字数ではなく「自分の経験/事例が1つ入っているか」でゲートを設ける | コピペ対策 |
| **内省の強制（リフレクションジャーナル）** | 各セッション終了時に「今日一番驚いたこと」を入力しないと次に進めない | 振り返り習慣の形成 |
| **複数解答の可視化** | 「このクエストに正解はない。あなたの選択記録は保存されます」と明示 | 正解探しからの解放 |
| **ピア対話誘発イベント** | 「隣の人の選択肢を聞いてみよう」というゲーム内ミッション | 教室内の対話促進 |
| **AI回答の禁止ルール（ゲーム内ルール）** | ゲームのルール設定として「AIツールの使用 = ゲームオーバー（ペナルティ）」ではなく「AIに聞いた内容を書いてみよう、でも"なぜ自分はそれを選ぶのか"を追記せよ」というフロー | AI利用の禁止でなく批判的消費の訓練 |
| **タイムプレッシャーの排除** | 速さを評価しない。ゆっくり考えた証拠（記述の詳細さ）を評価 | 熟考を促す |
| **問いの進化ログ** | 最初に立てた問いと、今の問いを並べて見られる機能 | メタ認知の促進 |

## 8. 学校導入を見据えた設計

### 教員管理画面の構想

```
[ダッシュボード概要]
- クラス全体の探究力4軸レーダーチャート（匿名集計）
- 生徒ごとの進捗状況（章・セクション）
- 内省ジャーナルの要約（AIが要約、ただし原文も参照可）
- 「今週の対話を促したい生徒」アラート

[個別生徒ビュー]
- 探究力の変化グラフ（学期初→現在）
- 分岐選択の傾向分析（どのタイプの問いを選びやすいか）
- ジャーナル全文閲覧
- 教員メモ追記機能

[授業支援]
- 本日の「クラス共有トピック」自動生成（各生徒の選択から）
- ルーブリック連動評価シート出力（PDF）
- 学習指導要領との対応マッピング表示
```

### ルーブリック連動

学習指導要領「総合的な探究の時間」の評価観点と直接連動：

| 評価観点 | ゲーム内計測方法 |
|---------|---------------|
| 知識・技能（探究の方法を理解） | 各フェーズのクリア状況 |
| 思考・判断・表現（課題を設定し情報を活用） | 分岐選択の根拠記述の質 |
| 主体的に学習に取り組む態度 | ジャーナル記述回数・自発的な深掘り行動数 |

## 9. MVP範囲の仮提案

### MVP: 第1章「問いを立てる」単体検証

**理由**: 探究のスタート地点。ここが機能しなければ後の章も機能しない。最も差別化が問われるフェーズ。

**MVP内容（6〜8コマ分）**:

```
[プロローグ]
- 世界観の提示（静的テキスト+イラスト）
- 最初の「問いカード」との出会い

[第1章コア体験]
1. 日常の「違和感」発見イベント（現象の観察）
2. 表面の問いを立てる（自由記述）
3. AIナビ（問いを返すだけ）との対話 × 3ターン
4. 問いを深掘りする分岐選択
5. 根本の問いへの書き直し（=必然性の一本化体験）
6. 内省ジャーナル記述（強制）
7. 「問い力」スキルゲイン + 称号「問いの芽吹き」獲得
8. 教員ダッシュボードへのデータ反映確認
```

**技術的MVP**:  
- Webブラウザ動作（Unity WebGLではなくReact/TypeScript推奨）
- シングルページ完結型（インストール不要）
- 管理画面は最小限（Google Sheets連携でも可）

**検証指標**:
- プレイヤーが「表面の問い」から「より深い問い」に書き換えたか（Before/After比較）
- 内省ジャーナルの記述量・具体性の変化（セッション1→セッション6）
- 教員がデータを「使えた」と感じるか（toB採用判断の鍵）

## 10. オープン論点リスト

設計を進める前に決めるべき問い（優先度順）

### 優先度：高

**Q1. ゲームの「主役」は探究テーマか、自己理解か？**  
現在の設計は「探究プロセスのスキル化」に寄っているが、LIGHTHOUSEの哲学「必然性の一本化」は本質的に「自分が何者か」という自己探究に近い。「外部テーマを探究するゲーム」か「自分自身を探究するゲーム」かで世界観と物語構造が大きく変わる。

**Q2. 1セッションのプレイ時間をどう設定するか？**  
授業45〜50分内で完結するセッション設計が必要か、宿題・自習を前提にするか。学校の授業形態（一斉・グループ・個人）との相性が設計を左右する。

**Q3. 「物語」はどこまでプレイヤーが作るのか？**  
完全固定ストーリー（VN的）vs. プレイヤー記述が物語を生成する（生成型）vs. その中間。記述負荷とゲーム性のバランスをどこに置くか。

### 優先度：中

**Q4. クラス・学校間の「比較/競争」要素をどう扱うか？**  
協調学習を促進したいが、ランキングや競争要素は動機付けに有効。探究学習に競争は馴染まないという価値観もある。設計方針を明確化する必要がある。

**Q5. 教員のゲームリテラシーをどこまで前提にするか？**  
ゲームに不慣れな教員でも運用できるか、ゲームを積極的に活用したい教員向けに最適化するか。

**Q6. 探究テーマの設定タイミング**  
ゲーム内の問いとプレイヤー自身の現実の探究テーマをどう連動させるか。完全ゲーム内完結か、現実の探究テーマをゲームに持ち込ませるか。

### 優先度：低（後回し可）

**Q7. マルチプレイ/ピア要素の技術実装をどうするか**  
**Q8. セーブデータの扱いと個人情報保護**  
**Q9. コンテンツのローカライズ・地域差対応**
