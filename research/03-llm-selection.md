## 1. エグゼクティブサマリー

**最終推奨: Claude Haiku 4.5 をメイン採用（Sonnet 4.6 をオプション上位）**

GDDが要求する「答えを返さず問いを返す」の絶対原則に対し、Claudeは**システムプロンプトへの追従性の高さ**・**日本語対話自然性**・**短文制約下での安定性**の3点で優位に立つ。Geminiは料金の安さと無料枠という魅力があるが、systemInstruction追従の揺らぎ・安全フィルターのデフォルト挙動の不確実性がMVPフェーズでのリスクとなる。データ保持方針は両者ともAPI有料利用時は学習利用OFFで同等だが、Anthropicは SOC 2 Type 2 / ISO 27001 / HIPAA対応と教育機関向け「Claude for Education」プログラムを持ち、学校導入時の説明責任で優れる。MVP 100名規模の月額コストはClaude Haiku 4.5で**約$4〜$8**と極めて低水準に収まる。

## 3. 「問いを返す」適性の評価

### GDD §5-3・§7が要求する仕様

```
禁止: 断定・評価・正解提示・指示・称賛・要約・否定・長文応答
必須: 疑問文1文・30〜80字・プレイヤーの言葉を直接引用
制約: max_tokens=80, temperature=0.7, stop sequence「。\n」
```

### Claude の「問いを返す」適性

**強み**
- **システムプロンプト追従性が業界トップクラス**: Anthropicの内部研究・外部開発者評価で一貫して高評価。GDDの「禁止パターンリスト」をシステムプロンプトに具体例付きで書けば、そのまま機能する確率が高い
- **日本語の対話自然性**: Claude は入力言語を自動検出して応答言語をマッチさせる設計（GitHub issue等で実証）。中高生の砕けた日本語表現に対し、教訓的にならない自然な疑問文を返す品質が高い
- **短文制約下での安定性**: max_tokens=80 での1文疑問文という制約に対し、切り捨て時の文境界が比較的きれいに処理される
- **事実質問への「答えてしまう」リスク**: 「みのりのSNSの投稿はいつ？」等の事実質問にうっかり答えるリスクについて、Claudeはシステムプロンプトで「答えを提示しない」を明記すれば高い精度で守る

**弱み・リスク**
- 無料枠がなく、プロトタイプ段階からコストが発生する
- 過度に丁寧な応答スタイルが「ですます体」になりがちで、GDDが求める「距離感を保ちつつ親しみやすい」トーンの微調整が必要

**想定リスクシナリオ**
1. `max_tokens=80` + `stop sequence` を設定しても、日本語では句点位置によって1文が80字を大幅に超える場合がある → GDDの **アプリ層チェック**（断定文再生成ロジック）で対応
2. 「依頼解決した？」等の二択質問に対し、「解決しましたか？」と反復するだけの薄い問いが生成されるケース → few-shot例（§7-2の12パターン）を多めに組み込むことで対応

### Gemini の「問いを返す」適性

**強み**
- **コスト**: Flash 系は Claude の1/10以下の価格帯。プロトタイプ〜小規模検証フェーズで財布に優しい
- **超長文コンテキスト**: 2.5 Flash は大きなコンテキストウィンドウを持ち、将来的にジャーナル履歴を全部渡す設計にも対応しやすい
- **Google Workspace for Education との親和性**: 学校がGoogle環境を使っていれば認証連携（Google SSO）のハードルが低い

**弱み・リスク**
- **systemInstruction 追従の揺らぎ**: 開発者コミュニティで「systemPromptが機能しない」「英語で応答が返ってくる」という報告が複数ある。GDDの禁止パターンを徹底させるには追加チューニングコストが増える可能性
- **Safety filter のデフォルト挙動**: Gemini 2.5 以降はデフォルトがフィルターOFF（`HARM_BLOCK_THRESHOLD_UNSPECIFIED`）。「中高生向け教育プロダクト」として学校に説明する際、自社でフィルターを設定している証跡が必要
- **「事実を答えてしまう」リスクが高い**: Geminiは一般的に知識豊富な回答をしようとする傾向が強く、「答えを持たないAI」を演じさせることへの抵抗感がある。few-shotを多数入れないと安定しない
- **透明性**: Gemini APIのsafety policy公開情報はあるが、学校向け説明に特化したドキュメントが少ない

**想定リスクシナリオ**
1. 「みのりが悲しいのはなぜですか？」に対し、物語の文脈から答えを導いて「友達がSNSで〜したからではないか」と答えてしまう
2. Safety filter が「子供の感情に関する記述」を過剰にブロックし、ジャーナル内省の問いに応答できない

## 4. コスト試算

### 前提条件（MVP想定）

| 条件 | 値 |
|------|---|
| 生徒数 | 100名 |
| 1日の往復数 | 5往復（AIへの問いかけ→返答） |
| 1ヶ月稼働日 | 20日 |
| 月間API呼び出し数 | 100 × 5 × 20 = **10,000回** |

### トークン試算

| 方向 | 内容 | 平均トークン数 |
|------|------|--------------|
| **入力** | システムプロンプト（キャッシュ後初回のみ）+ ジャーナル記述（100〜200字） | 約500〜800 tokens/回 |
| **出力** | 疑問文1文（30〜80字） | 約20〜40 tokens/回 |

**月間総トークン（中央値ベース）**
- 入力: 10,000回 × 650 tokens = **6,500,000 tokens (6.5 MTok)**
- 出力: 10,000回 × 30 tokens = **300,000 tokens (0.3 MTok)**

### Claude Haiku 4.5 での月額試算

| 項目 | 計算 | 金額（USD） |
|------|------|-----------|
| 入力（通常） | 6.5 MTok × $1.00 | $6.50 |
| 入力（プロンプトキャッシュ活用後） | キャッシュ効果で約60〜70%削減 → 実質約2〜2.5 MTok × $1.00 | **$2.00〜2.50** |
| キャッシュ書き込み（初回のみ） | 0.3 MTok × $1.25 | $0.38 |
| キャッシュ読み込み | 6.2 MTok × $0.10 | $0.62 |
| 出力 | 0.3 MTok × $5.00 | $1.50 |
| **合計（キャッシュ活用時）** | — | **約$4〜5/月** |
| **合計（キャッシュ未活用時）** | — | **約$8〜9/月** |

> **結論**: Haiku 4.5 + プロンプトキャッシュで月額 **$4〜$5**（約600〜750円）。100名規模なら1人あたり約6円/月。

### Claude Sonnet 4.6 での月額試算

| 項目 | 計算 | 金額（USD） |
|------|------|-----------|
| 入力（キャッシュ活用） | 実質2.5 MTok × $3.00 + キャッシュ費用 | 約$8.00 |
| 出力 | 0.3 MTok × $15.00 | $4.50 |
| **合計** | — | **約$12〜16/月** |

### Gemini 2.5 Flash での月額試算

| 項目 | 計算 | 金額（USD） |
|------|------|-----------|
| 入力 | 6.5 MTok × $0.125 | $0.81 |
| 出力 | 0.3 MTok × $0.75 | $0.23 |
| **合計** | — | **約$1〜1.5/月** |

> **Geminiの価格優位**: Gemini 2.5 Flash はClaudeの約1/4〜1/5の価格。ただし「品質安定性コスト（エンジニア追加工数）」を含めると実質的な差は縮まる。

| モデル | 月額（100名・20稼働日） | 1人/日コスト |

## 5. データ保持・教育利用適性

### Anthropic（Claude）の方針

| 項目 | 内容 | 評価 |
|------|------|------|
| API利用時の学習利用 | **デフォルトでOFF**（Commercial Terms対象）。消費者プランのオプトイン変更（2025年9月〜）はAPI利用者に**適用されない** | ◎ |
| Zero Data Retention（ZDR） | 選択顧客向けに提供中。Anthropicは2026年5月に新しい保持原則を策定予定 | ○ |
| コンプライアンス認証 | SOC 2 Type 2、ISO 27001、ISO 42001、HIPAA（2026年4月以降 native API で BAA 対応） | ◎ |
| 教育向けプログラム | **Claude for Education**（Teach For All提携・63カ国展開）。大学向けが主だが学校向けにも展開可 | ◎ |
| Trust Center | [trust.anthropic.com](https://trust.anthropic.com) で透明性報告・コンプライアンス状況を公開 | ◎ |
| 子ども・個人情報保護 | API利用時は `player_id` を乱数置換した上でAPIコール（GDD §9-3の設計で対応可能） | ○ |

**GDD §6-5（個人情報・要配慮データの取扱方針）との整合性**  
- GDD要件「ジャーナルテキストを送信する際は個人識別情報を除去」→ Anthropic API はデータプロセッサとして機能し、除去済みデータを処理するため適合
- GDD要件「研究目的利用は3者同意」→ Anthropic のデフォルトが学習不使用なため、研究利用フローを別途設計すれば整合

### Google（Gemini）の方針

| 項目 | 内容 | 評価 |
|------|------|------|
| API有料利用時の学習利用 | **OFFが明記**（Paid Services は製品改善に使われない）。2026年3月23日改訂の追加利用規約で確認済み | ◎ |
| 無料枠利用時 | 学習利用**あり**（コンテンツが Google の製品改善に使用される）。**教育プロダクトでは絶対に使用不可** | ✗ |
| コンプライアンス認証 | Google Cloud経由でSOC 2等。ただし Gemini Developer API（AI Studio）は Cloud とは別 | △ |
| 教育向けプログラム | Google Workspace for Education で別途対応。Gemini API 単体には教育専用プログラムなし | △ |
| 透明性 | 利用規約・プライバシーポリシーは公開されているが、教育機関向け説明の文書整備はClaudeより薄い | △ |
| 日本の個人情報保護法対応 | Google Cloud の DPA（Data Processing Addendum）を活用すれば対応可能 | ○ |

**学校導入時の説明責任上の懸念**  
Gemini Developer API（AI Studio）は Google Workspace for Education のデータ保護体制と**別のサービス**。学校・保護者への説明時、「GoogleのAI」としての安心感はあるが、具体的なデータ保護文書の引用が複雑になる可能性がある。

### 教育適性評価まとめ

| 評価軸 | Claude | Gemini Developer API | 判定 |
|--------|--------|---------------------|------|
| API利用時のデフォルト学習不使用 | ◎ | ◎（有料のみ） | 同等（有料前提） |
| 学校・保護者への説明容易性 | ◎（Trust Center・教育プログラム） | △（Workspace EDU と混同） | Claude優位 |
| 日本語個人情報保護法対応 | ○（DPA締結）| ○（DPA締結） | 同等 |
| 未成年者データの取扱い | ○（Constitutional AI設計） | ○（ポリシーあり） | 同等 |
| 緊急時の窓口対応 | ○（APIサポート） | ○（Googleサポート） | 同等 |

## 6. ガードレール実装容易性比較

GDD §7-4 が要求する三層ガードレール（プロンプト / モデル / アプリ）の実装容易性を評価する。

### 層1: プロンプトレベル（システムプロンプト）

| 比較軸 | Claude | Gemini |
|--------|--------|--------|
| システムプロンプトの扱い | `system` フィールドとして明示的に分離。`user/assistant` ターンと混じらない | `systemInstruction` として分離。ただし追従性のムラが報告される |
| 禁止パターンの追従 | few-shotとルールの組み合わせで高い安定性 | 追加の念押し指示が必要なケースがある |
| 具体例（few-shot）の組み込み | `<examples>` タグを使ったXML形式が推奨・実績あり | `examples` フィールドまたはシステムプロンプト内に記述可能 |
| max_tokens制約 | `max_tokens: 80` で確実に制限。API側で強制される | `maxOutputTokens: 80` で制限可能 |
| stop_sequence | `stop_sequences: ["。\n"]` で文末での強制停止 | `stopSequences` パラメータで同様に設定可能 |

**実装難易度**: Claude ≒ Gemini（同等）。ただしClaudeは追従性の実績が豊富。

### 層2: モデルレベル（APIパラメータ）

| パラメータ | Claude | Gemini |
|-----------|--------|--------|
| temperature | `temperature: 0.7`（直接設定） | `generationConfig.temperature: 0.7`（設定可能） |
| max output tokens | `max_tokens: 80` | `generationConfig.maxOutputTokens: 80` |
| stop sequence | `stop_sequences: ["。\n"]` | `generationConfig.stopSequences: ["。\n"]` |
| 応答形式強制 | JSON mode / XML / 自然文 いずれも対応 | JSON mode（`responseMimeType`）対応 |

**ストリーミング対応**
- Claude: Server-Sent Events（SSE）形式。`stop_reason: "refusal"` が返ればアプリ層でキャッチ可能
- Gemini: SSEおよびWebSocket（Live API）対応。フィルターブロック時は `finishReason: SAFETY` を返す

### 層3: アプリケーションレベル

| 実装要件（GDD §7-4） | Claude での実装 | Gemini での実装 |
|---------------------|----------------|----------------|
| 断定文チェック（「です」「ます」終わり検知→再生成） | 出力テキストのパターンマッチング + API再呼び出し | 同様（API非依存） |
| 指示文チェック（「〜してください」「〜しましょう」検知） | 同上 | 同上 |
| 2回失敗時のフォールバック文返却 | 定数文字列を返す（API非依存） | 同上 |
| 3回連続問いかけブレーキ | セッション状態管理（アプリ層・API非依存） | 同上 |
| 1ターン1問ルール | 出力の「？」の数をカウント（API非依存） | 同上 |

**アプリケーション層の実装はAPI非依存のため、両モデルで差はない。**

### エラーハンドリング比較

| エラー種別 | Claude | Gemini |
|-----------|--------|--------|
| レート制限 | `429 rate_limit_error` | HTTP 429 |
| 安全フィルター発動 | `stop_reason: "refusal"`（Claude 4系） | `finishReason: SAFETY` |
| フォールバック実装 | フォールバック文をアプリ層で返す設計が推奨 | 同様 |
| 障害時の可用性 | AWS Bedrock / Google Cloud Vertex AI 経由でも利用可能 | Google Vertex AI 経由でも利用可能 |

**教員・学校向けの説明責任**
- Claude: [Anthropic Trust Center](https://trust.anthropic.com) + [Safety Policy](https://www.anthropic.com/responsible-scaling-policy) + Transparency Report が整備されており、「このAIはどんな安全対策を持っているか」の説明が容易
- Gemini: [Google AI Principles](https://ai.google/principles/) + Safety Report は存在するが、学校向けの具体的ガイドラインはWorkspaceとの文脈が混在

## 7. 併用パターン3案と評価

### パターンA: Claude メイン + Gemini フォールバック

**構成**: AIナビゲーター（問いを返す）をClaude Haiku 4.5で処理。Claude APIが429/障害時にGemini 2.5 Flashへ自動切り替え。

| 評価軸 | 詳細 |
|--------|------|
| 対話品質 | 主路がClaudeなので品質安定。フォールバック時はGeminiのプロンプト追従差を許容する必要がある |
| 実装複雑度 | 中程度。両モデルのAPIラッパー + フォールバックロジックが必要。フォールバック文の返却を優先しても可 |
| 月額コスト | Claude: $4〜5 + Gemini フォールバック（稀）: ほぼ無視。合計 $4〜5 |
| 教育的説明責任 | 「基本はClaude（Anthropic）、落ちたらGemini（Google）」と説明できる。複雑さは低い |
| 推奨度 | **★★★★☆（中高推奨）** |

### パターンB: 役割分担（対話=Claude / ジャーナル要約=Gemini）

**構成**: リアルタイムの「問い返し」対話はClaude Haiku 4.5。各コマ末や部末の「問いの進化ログ生成・ジャーナル要約（教員ダッシュボード用）」はGemini 2.5 Flash（バッチ処理）で実施。

| 評価軸 | 詳細 |
|--------|------|
| 対話品質 | 対話はClaude安定。要約はGeminiの長文処理力を活かせる |
| 実装複雑度 | 高。2つのAPIエンドポイント管理 + 役割による振り分けロジックが必要 |
| 月額コスト | Claude（対話）: $4〜5 + Gemini（要約バッチ）: $0.5〜1。合計 $4.5〜6 |
| 教育的説明責任 | 「生徒との対話はAnthropic Claude、先生向け集計はGemini」と役割を説明できる |

## 8. 最終推奨

### 推奨案: **Claude Haiku 4.5 単独採用（MVP段階）**

#### 推奨理由3点

1. **「問いを返す」安定性**: Claudeはシステムプロンプトへの追従性が業界でも定評があり、GDD §7-3の禁止パターンリスト＋§7-2のfew-shot例をそのまま流し込める。事実質問に答えてしまうリスクが低く、中高生の多様な記述パターンに対しても疑問文1文を安定して返す実績がある。Geminiのような「追従が揺らいだ際の対処工数」を見込む必要がない。

2. **教育機関への説明責任**: Anthropicは「Claude for Education」プログラム（63カ国・学校向け展開）、SOC 2 Type 2・ISO 27001・HIPAA対応、Trust Center公開と、学校導入時に保護者・教育委員会への説明に必要な材料が揃っている。API利用時はデフォルトで学習データ利用OFFが保証されており（消費者向けポリシー変更の影響なし）、生徒の内省ジャーナルを扱うプロダクトとして適切な根拠を示せる。

3. **MVPコストの実質的無害さ**: Claude Haiku 4.5 はプロンプトキャッシュ活用で月額$4〜5（約600〜750円）。100名規模では1人あたり月6円以下。将来的に規模が10倍になっても月額$50以下。コスト優位性を理由にGeminiを選ぶ根拠がMVP段階では成立しない。

#### モデル選択の判断木

```
Q1: 応答品質・プロンプト追従の安定性を最優先するか？
  → YES → Claude Haiku 4.5
  → NO（コスト最優先）→ Gemini 2.5 Flash

Q2: 学校への説明責任・コンプライアンス文書の充実度を重視するか？
  → YES → Claude（ダントツ）
  → NO → どちらでも可

Q3: 月額コストが$50を超える規模になるか（約1,000名以上）？
  → YES → Gemini を検討対象に加える
  → NO（100〜500名） → Claude Haiku で十分
```

#### 移行戦略

| フェーズ | 採用モデル | 判断基準 |
|---------|-----------|---------|
| **MVP（〜100名パイロット）** | Claude Haiku 4.5 単独 | 品質安定化優先。コストは月額$10以下で問題なし |
| **フェーズ2（500名展開）** | Claude Haiku 4.5継続 / 必要に応じSonnet 4.6上位移行 | 月額$20〜$40。プロンプトキャッシュ効率を測定後に判断 |
| **フェーズ3（大規模展開 1,000名〜）** | Claude主体 + Gemini役割分担（パターンB）を検討 | 月額コストが$50を超えたタイミングで役割分担を評価 |
| **A/B検証（任意）** | パイロット校で50名ずつ分割テスト | 対話品質の実測データが欲しい場合のみ。IRB等の倫理承認要確認 |
